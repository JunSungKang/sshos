# sshOS(시오스) 상세 제품 계획서

문서 판본은 v2이며 수정일은 2026년 11월 14일이다. 목표 제품 버전은 1.0.0이다. 이 문서는 사용자가 보는 동작과 완료 기준을 정의한다. 별도의 `02-development-plan.md`는 구현 구조와 검증 절차를 정의한다. 구현 담당자는 두 문서와 `spec-v2.json`을 함께 읽는다. v1 원문은 `history/v1/`에 보존한다.

sshOS(시오스)는 자체 홈, 기본 앱, 창 관리, 전송 작업 영역을 갖춘 오픈소스 데스크톱 도구다. 사용자는 이 환경 안에서 SSH로 연결한 리눅스 서버의 파일, 시스템 상태, 서비스, 프로세스, 로그를 마우스로 다룬다. 서버가 여러 대여도 sshOS(시오스) 작업 공간은 하나이며 각 앱 창이 작업 대상 서버를 명시한다.

### 1.3 이번 명세의 기능 경계

1.0.0의 완료 범위는 이 문서의 R01부터 R34까지다. 다음 기능의 릴리스 배정은 `후속 버전 미정`이다. 브라우저 호스팅, 모바일 앱, Linux 클라이언트, SSH agent와 ProxyJump, 원격 데스크톱 스트리밍, 사용자 입력 터미널, Docker와 Kubernetes 전용 앱, 패키지 설치, 사용자·방화벽 관리, 부팅·종료, 파일 내용 편집, chmod/chown UI, 서버 간 직접 전송, 전송 이어받기, 플러그인, AI 명령 생성, 팀 계정·클라우드 동기화, 다국어 선택, 자동 업데이트가 해당한다. 구현자는 명세 변경 없이 이 기능들의 버튼이나 동작을 추가할 수 없다.

### 1.4 소스 공개와 라이선스 정책

MIT는 재사용과 배포를 폭넓게 허용하며 파생 소프트웨어에 소스 공개 의무를 부과하지 않는다. 이 판본은 사용자에게서 받은 MIT 우선 조건을 외부 구성요소 선택에 적용하고, sshOS(시오스) 자체의 공개 의무에는 AGPL-3.0-only를 선택한다. 사용자 목표를 실행 가능한 라이선스 정책으로 구체화한 계획이며 실제 프로젝트 라이선스 고지는 구현 단계에서 추가한다. [MIT 원문](https://opensource.org/license/mit)

AGPL의 소스 제공 의무는 적용 대상 저작물의 배포와 수정본의 원격 네트워크 이용 조건에 따라 발생한다. 배포 시에는 수령자에게 필요한 대응 소스를 제공하고, 네트워크로 사용자가 상호작용하는 수정본에는 해당 사용자가 소스를 받을 수 있는 수단을 제공한다. 이 계획은 코드를 복제·수정·결합한 결과가 적용 대상 저작물인 경우에 이 조건을 적용한다. [AGPL 5·6·13조](https://opensource.org/license/agpl-3.0)

| 이용 형태 | v2의 처리 기준 |
| --- | --- |
| sshOS(시오스) 자체 또는 적용 대상 파생물을 배포 | 해당 버전의 대응 소스와 AGPL 고지를 수령자에게 제공한다. |
| 수정한 sshOS(시오스)를 원격 네트워크 사용자에게 제공 | 해당 사용자에게 수정본의 대응 소스 제공 기능을 넣는다. |
| sshOS(시오스)로 서버·파일·독립 프로그램을 관리 | 관리 대상의 라이선스는 해당 저작물의 조건을 따른다. SSH 연결만으로 관리 대상에 AGPL을 적용하지 않는다. |
| 배포 없이 개인적으로 수정·실행 | AGPL의 해당 이용 조건을 적용한다. 모든 내부 코드의 전 세계 공개를 의무라고 표현하지 않는다. |
| 독립 프로그램을 함께 배포하거나 통신으로 연동 | 실제 결합 방식으로 적용 범위를 판단한다. 한 컴퓨터에서 실행되거나 파일을 교환한다는 이유만으로 전체를 파생물로 판정하지 않는다. |

표의 경계는 라이선스의 covered work, aggregation, network interaction 조건을 따른다. 독립성과 결합 관계에 법적 판단이 필요한 사례는 관계를 문서화해 개별 검토한다. 제품의 마케팅 문구는 `sshOS와 그 적용 대상 파생물의 소스 공개 의무를 유지하는 오픈소스`로 사용한다. [AGPL 0·2·5·13조](https://spdx.org/licenses/AGPL-3.0-only.html)

외부 라이선스 선택은 MIT 대안의 기능 적합성부터 판단한다. 적합성은 해당 R 요구사항의 기능, 대상 OS, 보안 수정 가능성, 고정 버전 설치 가능성을 충족하는지로 기록한다. MIT 대안이 이 조건을 충족하지 못하면 그 근거와 선택한 다른 OSS 라이선스를 기록한다. `오픈소스`라는 명칭만으로 라이선스 호환성을 통과 처리하지 않는다. [OSI 오픈소스 정의](https://opensource.org/osd)

sshOS(시오스)가 작성한 코드에는 SPDX `AGPL-3.0-only`를 사용한다. 외부에서 가져온 파일은 출처·원저작권·원라이선스를 보존한다. 프로젝트 전체에 `MIT OR AGPL-3.0-only` 선택지를 부여하거나 MIT 원문에 별도 공개 의무를 붙인 변형 라이선스를 만들지 않는다. 동일한 프로젝트 규칙으로 소스·문서·빌드 스크립트를 관리하고 외부 이미지·아이콘·글꼴은 각 자산의 원래 조건을 기록한다.

### 1.5 오픈소스 기여와 배포 준비

개발 단계에서 `CONTRIBUTING.md`에 환경 준비, R·T·C ID를 사용하는 변경 설명, 테스트, 권리·출처 확인, 기여 코드의 AGPL-3.0-only 적용을 명시한다. 의존성 수정은 upstream 이슈 재현 자료와 최소 패치로 분리해 준비하고, 공개 제출은 사용자의 해당 외부 write 지시에 따른다. 실제 외부 기여의 채택 여부를 제품 기능의 완료 기준으로 삼지 않는다.

공식 sshOS(시오스) 릴리스는 설치 파일과 동일한 버전·commit의 소스 아카이브, lockfile, 빌드·설치 스크립트, 라이선스와 외부 고지를 함께 제공한다. `설정 → 제품 정보`에서 라이선스 원문과 해당 버전 소스 아카이브 저장 기능에 접근할 수 있어야 한다. 프로젝트 기여 정책과 상류 라이선스의 관계는 개발 계획서 13장에 고정한다.

## 2 사용 경험과 화면 규격

### 2.1 공통 작업 공간

앱 시작 시 로컬 작업 공간을 즉시 연다. 연결 목록이 비어 있으면 홈 중앙에 `서버 연결 추가` 버튼을 표시한다. 홈에는 저장된 서버 카드와 열린 창 목록을 표시한다. 카드에는 별칭, `사용자@호스트:포트`, 연결 상태, 확인된 서버 OS를 표시한다. CPU나 서비스 통계를 홈 카드에 중복해서 넣지 않는다.

기준 화면은 1600 × 1000 CSS px이며 최소 앱 창 크기는 1100 × 720 CSS px다. 좌표 원점은 앱 콘텐츠의 왼쪽 위다. 호스트 OS의 바깥 창 테두리는 이 좌표에서 제외한다.

| 영역 | 고정 규격 | 동작 |
| --- | --- | --- |
| 상단 막대 | 높이 56 px, 전체 너비 | 왼쪽 `sshOS`, 중앙 열린 창 탭, 오른쪽 연결 수와 전송 영역 열기 버튼 |
| 앱 실행 막대 | 상단 아래부터 전송 영역 위까지, 너비 88 px | 홈·연결·파일·시스템·서비스·프로세스·로그·설정 순서의 아이콘과 텍스트 |
| 작업 영역 | x=88, y=56, 폭 W−88, 높이 H−152 | 홈 또는 앱 내부 창 표시 |
| 상시 전송 영역 | 화면 아래 높이 96 px, 전체 너비 | 활성 작업 요약과 최근 활성 전송 2개, 전체 전송 창 열기 |
| 전체 전송 창 | 다른 앱과 같은 내부 창 | 모든 전송·폴더 작업·오류·완료 기록 |

전송이 0개이면 하단에 `진행 중인 전송 없음`을 표시한다. 파일 앱, 서비스 앱, 홈, 연결 오류 화면에서도 하단 영역을 유지한다. 앱 전체가 최소화된 동안의 진행 확인은 앱을 다시 열었을 때의 현재 상태와 완료 알림으로 제공한다.

### 2.2 창 관리

파일·시스템·서비스·프로세스·로그 창은 생성 시 `serverId`를 고정한다. 창 제목은 `앱 이름 · 서버 별칭`이며 그 아래에 `사용자@호스트:포트`를 표시한다. 다른 서버 선택은 새 창을 생성한다. 이미 해당 앱과 서버의 창이 있으면 그 창을 전면으로 올린다. 파일 앱도 서버당 하나의 창을 사용한다.

연결·전송·설정은 서버에 종속되지 않는 단일 창이다. 홈 버튼은 열린 창을 닫지 않고 홈을 표시한다. 상단 열린 창 탭을 누르면 해당 창으로 돌아간다. 앱 실행 막대에서 서버가 필요한 앱을 누르면 연결된 서버 선택기를 열며 마지막 선택 서버를 먼저 표시한다.

내부 창은 이동, 크기 조절, 최소화, 최대화, 복원, 닫기를 지원한다. 최소화는 상단 탭으로 보낸다. 최대화는 작업 영역을 채운다. 닫기는 창 상태만 제거하며 전송과 서버 연결의 수명은 연결·전송 기능의 명시적 동작으로 관리한다. 제목 막대를 두 번 클릭하면 최대화와 복원을 전환한다. 12개 창이 열려 있으면 추가 생성 요청에 `열린 창 12개를 모두 사용 중입니다`를 표시한다.

파일 창의 기본 크기는 960 × 600, 최소 크기는 640 × 420이다. 나머지 창은 기본 720 × 520, 최소 560 × 400이다. 사용 가능한 공간이 기본 크기보다 작으면 최소 크기 이상으로 축소한다. 새 창은 작업 영역 왼쪽 위에서 24 px씩 누적 이동하며 제목 막대 전체가 작업 영역에 남도록 보정한다. 창은 상단 막대, 앱 실행 막대, 전송 영역을 덮지 않는다. 실행을 종료할 때 창 종류, 서버 ID, 좌표, 크기, 마지막 경로를 저장한다. 재실행 시 서버 관련 창에는 `연결 필요`를 표시하고 연결 버튼을 제공한다.

## 3 연결과 인증

### 3.1 연결 입력

연결 폼의 필드는 별칭, 호스트, 포트, 사용자 이름, 인증 방식, 비밀번호 또는 키 파일, 키 암호, 자격 증명 저장 선택이다. 별칭은 1–64자, 호스트는 1–253자, 사용자 이름은 1–64자다. 필드 양 끝 공백을 제거하고 NUL·줄바꿈은 거부한다. 호스트는 DNS 이름, IPv4, IPv6 원문을 허용하며 포트는 별도 정수 1–65535, 기본 22다. 호스트에 프로토콜과 경로가 입력되면 오류를 표시한다. 이름은 대소문자를 구분해 저장한다.

인증 방식은 `비밀번호`와 `키 파일` 두 가지다. 비밀번호는 공백을 포함해 입력 그대로 사용한다. 키는 Ed25519 OpenSSH, RSA OpenSSH 또는 PEM, ECDSA OpenSSH 형식과 각 형식의 암호화된 키를 검사 대상으로 한다. RSA는 RSA-SHA2 서명을 사용한다. 잘못된 키 형식과 잘못된 키 암호는 서로 다른 오류를 표시한다. 키 파일은 운영체제 파일 선택기로 지정한다. 키 본문을 서버 프로필에 복사하지 않는다. 자격 증명 저장은 기본 꺼짐이다.

연결 중인 프로필을 수정하면 `다음 연결부터 적용됩니다`를 표시하고 현재 세션은 연결 당시의 프로필 사본을 사용한다. 삭제 요청에는 해당 서버 작업 중단과 연결 종료를 먼저 확인한다. 연결이 종료되고 활성 작업이 최종 상태로 기록된 뒤 프로필과 저장된 자격 증명을 삭제한다. 전송 이력에는 삭제 당시 서버 별칭을 보존한다.

### 3.2 호스트 확인과 연결 상태

첫 연결은 서버 주소, 포트, 키 알고리즘, SHA256 지문을 보여 주고 `확인 후 연결` 또는 `취소`를 받는다. 이미 저장된 키와 다르면 `서버의 호스트 키가 변경되었습니다`를 표시하고 연결을 중단한다. 키 교체는 설정의 해당 서버 신뢰 기록에서 기존·새 지문을 보고 별도로 확인한다. 두 번째 SSH 연결을 파일 전송용으로 열 때도 같은 신뢰 기록을 검증한다.

상태는 `disconnected → connecting → awaiting_host_confirmation → authenticating → probing → connected` 순서다. 기존 신뢰 기록이 일치하면 확인 상태를 건너뛴다. 사용자 취소는 `disconnected`, 연결 실패는 `error`, 예상하지 못한 끊김은 `disconnected`와 실패 원인을 남긴다. TCP·SSH handshake·인증 전체 제한은 확인창 대기시간을 제외한 30초, 원격 탐지는 15초다. 호스트 확인과 인증 입력 대기는 각각 120초다.

접속 성공 후 서버 OS, UID, HOME, systemd, SFTP 사용 가능 여부를 확인한다. 지원 OS이면서 SFTP를 사용할 수 있으면 파일 앱을 제공한다. systemd 또는 서버 도구가 없으면 해당 앱에 필요한 구성요소 이름을 표시한다. 원격 파일 접근 범위는 접속 계정의 실제 권한을 따른다.

### 3.3 연결 종료

대상 서버에 대기·실행·완료 확인 중인 전송 또는 서버 변경 작업이 있으면 작업 수를 표시하는 확인창을 연다. 선택지는 `연결 유지`와 `작업 중단 후 연결 종료`다. 후자는 새 작업을 막고 취소를 요청한 뒤 세션을 닫는다. 작업 결과를 확정할 수 없으면 `결과 확인 필요`로 남긴다. 다른 서버의 작업은 계속 실행된다.

## 4 파일 앱

파일 앱은 좌측 폴더 트리, 상단 이동·경로·작업 도구, 우측 파일 목록, 하단 항목 수로 구성한다. 트리 너비 기본 208 px, 조절 범위 160–320 px다. 경로 이동과 트리 선택은 같은 현재 경로를 공유한다. 트리 노드는 펼칠 때 해당 디렉토리만 조회한다. 접속 직후 현재 경로는 서버가 확인한 HOME이다.

파일 목록은 이름, 종류, 크기, 수정 시각, 권한, 소유 UID를 표시한다. 정렬은 폴더 우선, 그다음 이름의 Unicode 코드포인트 오름차순이며 열 제목 클릭으로 오름차순·내림차순을 전환한다. 숨김 파일은 기본 숨김이며 `숨김 파일 표시` 선택을 파일 창에 저장한다. 검색은 현재 폴더에 이미 조회된 이름의 대소문자 무시 부분 일치다. 재귀 검색으로 확장하지 않는다.

다음 작업을 제공한다.

| 동작 | 처리와 완료 조건 |
| --- | --- |
| 뒤로·앞으로·상위 폴더 | 창별 경로 이력 사용, 같은 폴더 재선택은 이력 추가 없음 |
| 경로 입력 | 절대 POSIX 경로만 허용, Enter로 조회, 성공한 경로만 이력에 추가 |
| 폴더 생성 | 이름 한 개 입력, `/`·NUL·`.`·`..` 거부, 이미 존재하면 오류 |
| 이름 변경 | 같은 부모 안에서 변경, 목적지가 존재하면 오류, 변경 후 재조회 |
| 삭제 | 선택한 전체 경로와 항목 수 표시 후 확인, 재귀 삭제는 심볼릭 링크를 따라가지 않음 |
| 업로드 | 로컬 파일·폴더 선택 또는 OS에서 파일 목록 영역으로 드롭 |
| 다운로드 | 선택한 파일·폴더를 운영체제 폴더 선택기로 정한 로컬 목적지에 저장 |
| 상세 정보 | 경로·종류·정확한 바이트 수·시각·권한·UID·GID·링크 대상 표시 |
| 텍스트 미리보기 | 일반 파일 최대 1 MiB, UTF-8 유효 텍스트만 표시, HTML도 문자 그대로 표시 |

다중 선택은 Ctrl/Cmd 클릭과 Shift 범위 선택을 지원한다. 폴더와 일반 파일을 함께 선택할 수 있다. 동일 하위 경로가 부모 폴더 선택에 포함되면 전송·삭제 대상에서 한 번만 처리한다. 서버 간 드래그와 앱 내부 파일 이동 드래그는 1.0에서 동작하지 않는다. 원격 심볼릭 링크는 표시와 명시적 열기를 지원하며 폴더 전송에서는 건너뛴 항목으로 기록한다. 소켓·FIFO·장치 파일은 목록에 표시하고 전송 버튼을 비활성화한다.

Windows 다운로드 경로로 표현할 수 없는 파일명, 대소문자 충돌, 예약명은 항목별 충돌로 보여 주고 이름 변경 또는 건너뛰기를 받는다. 자동 이름 치환은 하지 않는다. 트리와 목록의 큰 데이터는 가상화하며 10,000개 항목 폴더에서 기본 조작의 반응 기준을 충족해야 한다.

## 5 비동기 SFTP 전송

### 5.1 작업 생성과 상태

사용자가 전송을 요청하면 200 ms 안에 전송 영역에 작업을 등록한다. 디렉토리는 먼저 `준비 중`으로 표시하고 파일 수와 전체 바이트를 조사한다. 조사가 끝나기 전에는 퍼센트를 표시하지 않는다. 일반 파일은 크기를 확인한 뒤 대기열에 넣는다. 파일·폴더 전송은 파일 앱을 닫거나 다른 앱으로 이동해도 진행한다.

내부 상태 이름과 표시 문구는 다음과 같다.

| 상태 | 표시 | 허용되는 다음 상태 |
| --- | --- | --- |
| discovering | 준비 중 | queued, conflict, skipped, failed, cancelling, interrupted |
| conflict | 이름 충돌 확인 필요 | queued, skipped, cancelling, interrupted |
| queued | 대기 중 | running, failed, cancelling, interrupted |
| running | 전송 중 | finalizing, cancelling, failed, interrupted |
| finalizing | 완료 확인 중 | completed, failed, interrupted |
| cancelling | 취소 중 | cancelled, interrupted |
| completed | 완료 | 최종 상태 |
| failed | 실패 | 최종 상태 |
| interrupted | 연결 끊김 또는 종료로 중단 | 최종 상태 |
| cancelled | 취소됨 | 최종 상태 |
| skipped | 건너뜀 | 최종 상태 |

재시도는 기존 작업 ID를 보존하고 새 작업 ID와 `retryOf`를 생성한다. 기존 실패 기록의 상태는 바꾸지 않는다. 새 작업은 현재 원본과 목적지를 다시 검사한다. 전송 복구 위치는 파일의 0 byte다.

### 5.2 진행 표시

파일별 표시값은 방향, 서버 별칭, 파일명, 원본·목적지, 확인된 전송 바이트, 전체 바이트, 퍼센트, 최근 3초 평균 속도, 예상 남은 시간, 상태다. 바이트 표시는 IEC 단위 KiB·MiB·GiB를 사용한다. 속도는 B/s 기반이다. 최근 3초 동안 전송이 없으면 속도 0 B/s, 남은 시간 `계산 중`으로 표시한다.

업로드는 서버가 쓰기 응답을 반환한 바이트를 센다. 다운로드는 로컬 쓰기 완료가 확인된 바이트를 센다. 화면 갱신은 최대 250 ms 간격으로 묶되 상태 변경은 즉시 보낸다. finalizing 동안은 99%를 상한으로 표시하며 목적지 확정과 검사 완료 후에만 100%와 `완료`를 표시한다. 0 byte 파일도 생성·닫기·확정이 완료되어야 완료다.

폴더 작업은 전체 대상 수, 완료 수, 실패 수, 건너뜀 수와 전송 바이트를 표시한다. 전체 바이트가 확정되면 실제 전송 대상 바이트 기준으로 진행률을 계산한다. 최종 상태는 모두 성공 시 `완료`, 실패가 하나 이상이면 `일부 실패`, 실패 없이 건너뜀이 있으면 `건너뜀 포함 완료`, 사용자가 취소하면 `취소됨`이다. 폴더 진행률 100%만으로 전체 성공을 판정하지 않는다.

폴더 전송은 파일 단위로 확정한다. 취소·일부 실패 시 이미 완료된 파일과 생성된 폴더는 작업 결과로 보존한다. 폴더 재시도는 실패·중단된 파일만 새 작업으로 만들고, 사용자가 취소한 폴더를 다시 전송하려면 새 업로드·다운로드를 선택한다. 완료된 파일을 rollback으로 삭제하지 않는다.

하단에는 실행 순서상 먼저 시작한 활성 파일 두 개를 표시한다. 활성 파일이 없으면 가장 먼저 생성된 준비·대기·확인 작업 두 개를 표시한다. 나머지는 `외 N개`와 전체 전송 창 버튼으로 접근한다. 완료 후 최근 결과 한 개를 10초 표시하고 활성 작업이 있으면 그 표시가 우선한다.

### 5.3 충돌과 취소

목적지에 같은 이름이 있으면 전송 시작 전에 원본과 목적지 크기·수정 시각을 보여 준다. 선택은 `덮어쓰기`, `다른 이름`, `건너뛰기`다. 폴더끼리 같은 이름이면 하위 내용을 병합하고 각 파일 충돌을 개별 처리한다. 일반 파일과 폴더의 종류가 충돌하면 다른 이름 또는 건너뛰기만 제공한다. 일괄 선택은 현재 사용자가 생성한 폴더 작업의 같은 종류 충돌에만 적용한다.

전송 데이터는 같은 부모 디렉토리의 `.sshos-part-<UUID>` 파일에 배타 생성한다. 성공 시 목적지 이름으로 확정한다. 덮어쓰기는 전송 완료까지 기존 목적지 파일을 유지한다. 앱 안에서 같은 서버·정규화된 목적지로 향하는 작업은 하나씩 처리한다. 외부 프로그램이 목적지를 변경한 흔적이 발견되면 충돌 확인을 다시 요청한다. 외부 프로그램과의 완전한 동시 변경 배제는 SFTP 기능 범위를 넘어가므로 1.0의 일관성 보장은 sshOS(시오스) 내부 작업에 적용한다.

취소 버튼은 준비·대기·전송 중에 제공한다. 완료 확인 단계가 시작되면 버튼 대신 `완료 확인 중`을 표시한다. 취소 응답은 1초 안에 화면에 나타나고, 네트워크가 정상일 때 5초 안에 전송을 멈춘다. 임시 파일 삭제에 실패하면 경로와 `임시 파일 정리 필요`를 기록한다. 임시 파일 정리는 앱이 생성한 UUID와 작업 기록이 일치하는 항목만 대상으로 한다.

### 5.4 앱 종료와 장애

앱 종료 시 활성 작업이 있으면 `계속 사용`과 `작업 중단 후 종료`를 제공한다. 종료 선택 시 최대 5초 동안 취소·정리 후 종료한다. 다음 실행에서 실행 중이던 기록은 `interrupted`로 복구한다. 연결을 다시 만들고 사용자 재시도 요청을 받은 뒤 전송을 새로 시작한다. 일시 정지 버튼과 자동 재전송은 1.0 UI에 제공하지 않는다.

## 6 서버 관리 앱

### 6.1 시스템

서버 호스트명, Ubuntu 버전, 커널, 아키텍처, 가동 시간, CPU 사용률, 메모리 사용량, `/` 파일시스템 사용량을 표시한다. 2초 간격으로 갱신하며 최근 60개 표본을 선 그래프로 보여 준다. CPU는 두 번의 `/proc/stat` 차이로 계산한다. 첫 표본은 `측정 중`이다. 메모리는 MemTotal−MemAvailable이다. 디스크는 루트 마운트의 총량·사용량·사용 가능량이다. 접근 실패는 0으로 치환하지 않고 필드에 `조회 실패`를 표시한다.

### 6.2 서비스

systemd의 시스템 `.service` 단위를 목록에 표시한다. 설치된 unit-file과 현재 로드된 unit을 합치고 중복은 정확한 unit 이름으로 제거한다. 인스턴스가 없는 template unit은 목록에서 제외한다. 이름 검색은 조회된 이름·설명의 대소문자 무시 부분 일치다. 목록에는 이름, 설명, ActiveState, SubState, 부팅 시 시작 설정을 표시한다. 5초마다 갱신한다.

서비스 상세에는 시작·중지·재시작과 로그 열기를 제공한다. 실행 전 서버, 정확한 unit 이름, 동작, 권한 방식이 표시된 확인창을 연다. 일반 권한을 기본으로 하고 `sudo 사용`을 선택하면 비밀번호 입력을 제공한다. 비밀번호가 없는 sudo 설정에서는 빈 입력으로 시도할 수 있다. 비밀번호는 작업 종료 시 폐기한다. sudo 인증 실패는 새 입력을 받으며 같은 입력의 자동 반복은 0회다.

서비스를 선택하고 연결이 정상이며 해당 unit의 변경 작업이 없으면 세 변경 버튼을 활성화한다. systemd가 거부하는 동작은 실제 실패 결과를 표시한다. 이름과 상태를 미리 추측해 명령 성공을 표시하지 않는다.

변경 요청 접수 후 같은 unit의 변경 버튼을 잠근다. 최대 30초 동안 결과와 ActiveState를 확인한다. 명령 종료 코드 0이어도 최종 상태를 확인하기 전에는 성공으로 표시하지 않는다. 시작·재시작은 ActiveState=active 또는 oneshot 서비스의 Result=success이며 실행이 끝난 경우 성공이다. 중지는 inactive인 경우 성공이다. 네트워크가 끊기거나 30초가 지나면 `결과 확인 필요`를 표시하고 상태 새로고침을 제공한다. ssh.service처럼 접속 자체에 영향을 줄 수 있는 서비스도 대상 이름을 명시하고 사용자가 확인한 동작을 실행한다.

### 6.3 프로세스

PID, 실행 파일명, UID, CPU 사용률, RSS 메모리를 2초마다 갱신한다. CPU는 두 표본 사이 프로세스 CPU 시간 차이를 서버 전체 논리 CPU 수로 정규화한 0–100% 값이다. 최초 표본은 `측정 중`이다. 이름과 PID로 검색한다. 종료 기능은 현재 로그인 UID 소유의 프로세스에 SIGTERM을 보내는 기능으로 고정한다. PID 1과 sshOS(시오스) 연결에 사용하는 셸·SSH 세션 조상 프로세스는 종료 대상에서 제외한다.

종료 전 서버, PID, 이름을 확인받고 PID와 시작 시각이 목록 조회 당시와 일치하는지 다시 검사한다. 다른 프로세스로 바뀌었으면 `프로세스가 변경되었습니다`로 중단한다. 종료 요청 뒤 최대 5초 동안 같은 프로세스의 소멸을 확인한다. 남아 있으면 `종료 요청 전달됨 · 프로세스 실행 중`으로 표시한다. 강제 종료 버튼은 제공하지 않는다.

### 6.4 로그

journald의 현재 계정이 읽을 수 있는 기록을 표시한다. 초기 범위는 최근 1시간 중 최신 500개이며 화면은 오래된 순서다. 시간 범위는 최근 1시간·24시간·7일 중 선택한다. 서비스 필터는 정확한 unit 이름을 사용한다. 중요도는 전체·오류 이하(priority 0–3)·경고 이하(0–4)·정보 이하(0–6)다. 검색은 현재 받은 메시지의 대소문자 무시 부분 일치다.

`실시간 보기`는 기본 꺼짐이다. 켜면 새 기록을 추가하고 최대 5,000개를 유지한다. 사용자가 위로 스크롤하면 자동 스크롤을 멈추고 `새 로그 N개`를 표시한다. 로그 한 항목은 시각, 중요도, unit, 메시지를 보여 준다. 파일 경로로 보이는 텍스트도 실행하지 않고 문자로 표시한다. 기록이 없을 때와 읽기 권한 오류는 서로 다른 상태다.

## 7 설정과 보존 데이터

설정은 연결 정보 관리, 저장된 자격 증명 삭제, 호스트 신뢰 기록 관리, 전송 기록 지우기, 작업 공간 초기화, 제품·지원 OS·라이선스·해당 버전 소스 정보를 제공한다. 제품 정보에는 저작권, 무보증 안내, AGPL-3.0-only, 라이선스 원문, 외부 고지 보기와 `이 버전 소스 저장` 버튼을 둔다. 원문과 소스 아카이브는 로컬 패키지에서 제공한다. 작업 공간 초기화는 창 배치와 마지막 경로만 초기화한다. 자격 증명 삭제는 다음 연결부터 입력을 요구하며 이미 연결된 세션의 종료는 연결 앱에서 수행한다.

전송 기록은 최종 상태가 된 뒤 7일 또는 1,000개 중 먼저 도달한 제한으로 정리한다. 활성 작업과 정리되지 않은 임시 파일 기록은 이 제한으로 삭제하지 않는다. 로컬 진단 로그는 5 MiB 파일 3개로 순환한다. 비밀번호·키 내용·키 암호·sudo 비밀번호·서버 로그 본문은 진단 로그에 남기지 않는다.

## 9 단계별 개발 순서

SDD를 추천 방법론으로 사용해 명세 승인 후 구현한다. 작업 방법 비교와 세부 작업 ID, 의존 관계는 개발 계획서에 정의한다.

| 단계 | 결과 | 종료 조건 |
| --- | --- | --- |
| M0 | 명세 승인과 개발 환경 준비 | 사용자 확정 요구와 D01–D15 구현값 반영, 판본 해시와 승인 메시지 기록, T10.1 라이선스 기준과 로컬 Git 준비 |
| M1 | OS처럼 사용하는 공통 환경과 실제 SSH 연결 | R01–R08, R24의 해당 검사 통과 |
| M2 | 파일 관리와 비동기 SFTP 0.1.0 | R09–R17의 검사 통과, 실제 업·다운로드 확인 |
| M3 | 시스템·서비스·프로세스·로그 0.2.0 | R18–R22의 검사 통과 |
| M4 | 대상 OS 검증과 1.0.0 패키지 | R01–R34 전부 통과, 대응 소스·의존성 고지·기여 문서 완성, 알려진 결함과 미검사 0개 |

0.1.0은 기본 연결과 파일 전송을 검증하는 중간 버전이다. 제공하는 완성 예상 이미지는 M4의 1.0.0 화면을 표현한다. 중간 버전에서 서비스 앱이 보이면 구현 완료 상태와 실제 사용 가능 여부가 일치해야 한다. 미완성 앱의 실행 버튼은 해당 마일스톤의 제품 화면에서 숨긴다.

## 10 문서와 이미지의 효력

동작과 범위는 이 문서, 구현 세부는 개발 계획서, 연결 관계는 `spec-v2.json`을 기준으로 한다. 이미지의 렌더링 오차가 동작·수치·상태표를 변경하지 않는다. 문서끼리 같은 항목의 값이 다르면 해당 기능 구현을 보류하고 충돌 항목을 수정한 새 판본을 만든다. 그동안 독립된 작업은 진행할 수 있다.

계획 작성 완료와 제품 개발 완료는 각각 기록한다. 현재 제품 검사 C01–C34의 상태는 `untested`다. 계획 작성 과정의 문서 검토 결과를 제품 검사 통과로 기록하지 않는다.

v2의 변경 근거는 사용자의 2026년 11월 14일 재계획 요청이다. 기존 제안 중 macOS·Windows와 Electron을 확정 요구로 반영하고, MIT를 프로젝트 라이선스로 제안했던 D11을 AGPL 계획으로 바꾸었다. R23·R26·R28을 보완하고 R31–R34를 추가했다. 개발 승인 상태는 pending이며 공개 라이선스 발행과 외부 게시 권한을 이 계획 수정으로 추정하지 않는다.
