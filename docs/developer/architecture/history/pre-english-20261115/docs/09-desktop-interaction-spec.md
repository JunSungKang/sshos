# sshOS(시오스) 데스크톱 상호작용 명세 v6

2026-11-15. 제품 구현 전의 실행 계약이다. [제품 계획](01-product-plan.md)과 [개발 계획](02-development-plan.md)의 R33–R38을 구체화한다. X11 대체 서버나 원격 그래픽 프로그램을 구현하는 문서가 아니다.

## 1. 창 구조와 배치

Electron BrowserWindow는 앱당 하나다. 연결 확인/OS 파일 선택은 OS dialog를 사용할 수 있다. 탐색기·뷰어·터미널 등 작업 창은 그 BrowserWindow renderer 안의 React DOM으로 구현한다. 창마다 BrowserWindow/webview/iframe을 생성하지 않는다. 창 이동·크기 조절은 Pointer Events와 pointer capture로 구현하며 외부 창 관리자 라이브러리를 추가하지 않는다. xterm.js는 터미널 영역에만 사용한다.

기본 창 최소1120×760 CSS px, 시안1600×1000. 상단44px, 하단 전송선반60px, 작업표시줄56px를 예약한다. 작업영역은 x=0,y=44,width=viewportWidth,height=viewportHeight-160이다. 바탕화면 아이콘은 이 영역 안에 있고 창 아래에 위치한다. 고정 사이드 메뉴를 두지 않는다. 상단과 하단은 내부 창으로 가릴 수 없다. 최대화는 이 작업영역까지만 확장하며 OS 전체화면 전환이 아니다.

창 최소 크기: 파일640×360, 텍스트480×320, 이미지480×320, 실행/터미널560×320, 연결640×400, 작업640×360, 설정560×360. 창을 처음 열 때 파일은 min(940,영역폭)×min(596,영역높이), 다른 창은 min(720,영역폭)×min(440,영역높이)로 한다. 첫 창은 영역 중앙, 후속 창은 직전 기본 위치에서 오른쪽/아래24px씩 옮긴 뒤 영역 안으로 clamp한다. 뷰포트 변경 시 모든 창의 크기/위치를 영역 안으로 clamp하고 40px 제목줄 전체를 접근 가능하게 유지한다.

색상: 바탕화면 #123C47, 패널 #F8FAFB, 본문 #16313B, 강조 #087F78, 상단/작업표시줄 #102D35. 배경 장식은 포커스·대비·성능 기준을 침범하지 않는다. OS 네이티브 UI를 복제해야 한다는 요구는 없다.

## 2. WindowManager 상태와 전이

창 모델은 `{windowId,kind,serverId|null,sessionGeneration|null,resourceId|null,bounds,restoreBounds,mode,restoreMode,focused,lastFocusedSequence}`다. mode는 normal/maximized/minimized, restoreMode는 normal/maximized다. 최소화 직전 mode를 restoreMode에 저장하고 bounds/restoreBounds를 유지한다. maximized 상태 bounds는 작업영역, restoreBounds는 마지막 normal 좌표다. 서버 창의 resourceId는 탐색기 상태·viewerId·executionId·terminalId 중 하나다. windowId를 SSH 채널 ID로 사용하지 않는다.

| 동작 | 필수 결과 |
| --- | --- |
| 제목줄 pointer down/이동/up | 버튼 위가 아닌 제목줄만 이동. pointer capture 후 animation frame당 최대1회 위치 반영. pointercancel/blur에서 drag 종료. 텍스트 선택과 원격 입력 없음 |
| 테두리/모서리 드래그 | normal에서만 resize. 최소크기와 작업영역 안으로 제한. xterm은 확정 행/열 변경만 원격에 알림 |
| 창 본문/작업표시줄 항목 선택 | 해당 창을 맨 앞으로 올리고 포커스. 다른 창의 서버/내용 변경 없음 |
| 최소화 | 현재 bounds와 normal/maximized 상태 보존, 본문 숨김, taskbar 항목 유지. 마지막으로 선택한 보이는 창을 포커스 |
| 복원 | 이전 normal/maximized 상태와 위치·크기·스크롤 복원. viewport 변경이 있으면 clamp |
| 최대화 | normal bounds 보존 후 작업영역 사용. 최대화 버튼 재선택은 보존 bounds 복원 |
| 제목줄 더블클릭 | normal↔maximized. 실행/닫기 등 제목 버튼 클릭은 이 동작에 합치지 않음 |
| 닫기 | §5의 앱별 규칙 적용. 숨기기와 자원 종료를 혼동하지 않음 |

전체 내부 창 최대12개, 파일 창 최대6개, viewer 합계4개. 한도 도달 시 기존 창을 임의 종료하지 않고 ‘창 한도에 도달했습니다’와 열린 창 목록을 표시한다. 연결·작업·설정은 각각 singleton이며 다시 열면 기존 창을 복원한다. 파일 아이콘은 선택 서버의 마지막 파일 창을 복원하며 ‘새 파일 창’ 명령으로 추가한다. 같은 서버/세대/canonical path의 같은 뷰어 종류는 기존 창을 복원한다. 다른 파일 또는 종류는 새 창이다.

## 3. 서버 정체성과 활성 서버

서버를 요구하는 앱에서 서버가 없으면 연결 창을 연다. 연결된 서버가1개면 그 서버를 선택하고2개 이상이면 명시적 선택기를 연다. 서버 선택기 확인 이전에는 SSH 명령을 보내지 않는다.

서버 창 포커스 시 상단 activeServerId를 그 창의 serverId로 바꾼다. 전역 연결/작업/설정 창을 포커스하면 마지막 activeServerId를 유지한다. 최초 상태는 없음이다. 모든 서버 창이 닫혀도 activeServerId는 마지막 선택을 유지하며 연결 해제 시 해당 서버의 ‘연결 끊김’을 표시한다. 상단 서버 선택은 새 앱의 기본 대상만 바꾸며 열린 창을 재지정하지 않는다.

창 제목은 `종류/파일명 · 서버 표시명`, 상세에는 username@host:port와 경로를 표시한다. 타 서버의 같은 파일명은 같은 자원으로 합치지 않는다. 연결 해제 시 파일 목록과 뷰어 내용은 ‘연결 끊김 · 마지막 조회 시각’의 읽기 전용 캐시로 남고 동작은 잠긴다. 새 generation 연결 후에는 사용자가 새로고침/다시 열기를 요청해야 유효 token과 새 내용을 받는다. 자동 재실행이나 이전 터미널 복원 연결은 없다.

## 4. 실행기·탐색기·작업 표시줄

바탕화면 아이콘은 연결·파일·터미널·설정. 시작 버튼은 동일 항목과 작업 관리자를 연다. 아이콘은 더블클릭 또는 선택 후 Enter로 실행하고 단일클릭은 선택만 한다. taskbar 항목은 단일클릭으로 복원/포커스하며 이미 활성인 창도 임의 최소화하지 않는다. 실행 중 프로그램 창은 파일 뷰어와 구분되는 아이콘과 실행 상태를 가진다.

탐색기는 좌측 트리와 우측 목록을 한 창에 둔다. 트리 접기/펼치기는 가능하지만 ‘트리 모드’ 별도 앱은 없다. 폴더 더블클릭/Enter는 이동, 일반 파일은 열기 판정, 실행은 context menu/toolbar ‘실행’만 사용한다. 실행 파일을 더블클릭했다고 프로그램을 자동 실행하지 않는다. 텍스트 뷰어에 파일 내용 저장 버튼은 없다. 다운로드는 전송 작업이며 파일 열기와 다르다.

목록 갱신은 사용자의 새로고침/폴더 이동 및 해당 창에서 시작한 GUI 파일 변경 성공 후 그 부모 폴더1회 조회다. 다른 창/사용자 변경을 주기적으로 polling하거나 watcher로 동기화하지 않는다. 실행 종료 후에는 ‘파일 목록 새로고침’ 버튼만 제공하고 자동 검색하지 않는다. viewer는 ‘마지막 읽음’ 시각과 수동 다시 읽기 버튼을 제공한다.

전송 선반은 연결/설정/최대화/최소화 상태에서도 항상 남고 실행 중 최대2개+대기/실패 개수+전체 작업 버튼을 표시한다. taskbar는 창을, 전송 선반은 파일 전송을 나타낸다. 창을 닫아도 전송 작업 행이 사라지지 않는다.

## 5. 창 닫기와 프로세스 수명

| 종류 | 닫기 결과 |
| --- | --- |
| 파일/연결/설정/작업 | 창만 닫음. 연결·전송·실행은 유지. 열린 확인 dialog는 취소 |
| 뷰어 | 읽는 중이면 해당 읽기 취소, buffer와 ImageBitmap/canvas 참조 해제. 공유 SSH 연결 유지 |
| 실행 출력, 실행 중 | ‘창 유지’ / ‘창만 닫고 계속 실행’ / ‘중지 요청’을 표시. 계속 실행은 작업 관리자에서 출력 창을 다시 열 수 있음 |
| 실행 출력, 종료 관측 후 | 창만 닫음. 메모리 출력은 세션 종료 또는 명시적 기록 닫기 때 제거. 디스크 출력 저장 없음 |
| 터미널 | ‘유지’ / ‘세션 닫기’ 확인. 세션 닫기는 채널을 닫고 로컬 입력 중단. 원격 프로세스 전체 종료를 보장하지 않음을 문구로 표시 |

실행 중지와 종료 판정은 개발 §19가 정본이다. 앱 전체 종료/연결 해제에서는 실행·터미널·전송 목록을 함께 보여주고 사용자 취소 또는 해제/종료를 받는다. 내부 창을 닫는 것과 BrowserWindow를 닫는 것을 동일 이벤트로 구현하지 않는다.

## 6. 키보드·입력·접근성

Tab은 활성 창의 조작을 이동한다. modal은 focus trap 후 닫을 때 원래 조작에 복원한다. taskbar 버튼을 키보드로 선택하고 Enter로 창을 복원할 수 있어야 한다. OS Alt+Tab/Cmd+Tab을 가로채지 않는다. 제목줄 메뉴에 ‘이동’·‘크기 조절’을 제공하고 키보드 화살표10px, Shift+화살표1px, Enter확정, Esc원복으로 조작한다. OS 기본 단축키를 전역 등록하지 않는다.

IME 조합 중 Enter는 파일 실행·삭제·터미널 제출로 이중 전달하지 않는다. 터미널 포커스에서 Ctrl+C는 원격 입력이고 텍스트 선택이 있는 경우 복사는 명시적 메뉴 또는 macOS Cmd+C/Windows Ctrl+Shift+C다. 붙여넣기는 macOS Cmd+V/Windows Ctrl+Shift+V와 메뉴로 제공하며 일반 브라우저 paste 이벤트의 중복 전송을 막는다. 비터미널 창은 일반 복사/붙여넣기를 따른다.

상태는 문자+아이콘, 일반 텍스트 대비4.5:1 이상. 창 role/label, 활성 표시, visible focus, 동작별 접근성 이름을 둔다. 사용자 OS reduced-motion 설정이면 최소화/복원/드래그 완료 애니메이션을 없애고 상태를 즉시 반영한다. 기본 최소화/복원 애니메이션150ms이며 GIF의 시간표는 제품 수치가 아니다.

## 7. 상태 저장과 수용 조건

창 위치·열린 파일·터미널 내용·입력 이력은 디스크에 자동 저장하지 않는다. 앱 실행 시 바탕화면과 연결 창으로 시작한다. renderer crash 동안 main/worker는 작업을 유지한다. 창 상태 metadata는 main 메모리에250ms debounce로 반영하며 복구 시 마지막 snapshot을 사용한다. 손실된 마지막250ms 위치 변화를 보장하지 않는다. 자원 상태는 worker snapshot으로 복구하고 내부 창 ID만으로 새 SSH 요청을 실행하지 않는다.

필수 실사용 검사: 세 서버에 같은 파일명을 열어 대상 오인 방지, 창12개 한도, 최소/최대 viewport와 배율, pointer cancel, 최대화 뒤 viewport 축소·복원, 줄어든 화면 밖 창 회수, 실행 중 최소화와 복원, 터미널 IME/resize/큰출력 중 드래그, renderer 재시작, reduced-motion, 키보드만 사용. 검사 절차/상태는 체크리스트가 관리한다. 그림이나 GIF 검수로 제품 동작 통과를 대신하지 않는다.
