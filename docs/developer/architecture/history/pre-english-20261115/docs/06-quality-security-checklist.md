# sshOS(시오스) v6 기능·품질·보안 체크리스트

기준일: 2026-11-15. 대상: 0.1.0. **제품 구현 미착수이며 아래 모든 검사는 `untested`다.** 이 문서는 [제품 계획서](01-product-plan.md)와 [개발 계획서](02-development-plan.md)의 계약을 검사 단위로 연결한다. 새로운 정책·지원 범위·수치를 추가하지 않는다. 수치·알고리즘·Desktop/runtime의 규범은 [개발 계획서](02-development-plan.md)와 [데스크톱 상호작용 명세](09-desktop-interaction-spec.md), G0·G2·G3의 규범은 제품 계획서다. 충돌 시 해당 검사를 임의 완화하지 않고 명세 충돌로 기록한다.

## 검사와 실행 환경

- `F`는 기능·상태 계약, `Q`는 품질·환경·공개 판정, `S`는 신뢰·보안 계약이다. 한 행이 독립 검사 단위다. 행 안의 열거는 같은 계약을 검증하는 fixture 집합이며 일부 사례만 통과해서 행 전체를 pass로 바꾸지 않는다.
- 방법은 `automatic`(자동화된 단위·통합·UI·장애 주입), `visual`(이미지·화면 검수), `manual`(기록된 사람의 절차), `target`(실제 지원 OS·파일시스템·SSH 서버·배포물 검사) 중 하나다. `target`과 `manual`을 mock만으로 대체하지 않는다.
- 기본 서버 fixture는 개발 계획서의 품질·지원 환경 계약의 보안 업데이트가 적용된 Ubuntu 24.04 LTS·OpenSSH·ext4·일반 사용자다. 서버 CPU 두 종류와 클라이언트 세 target을 구분한다. 제한·장애 서버는 격리된 시험 환경에만 만든다. 실제 사용자 서버를 기본 시험 대상으로 삼지 않는다.
- 성능 행은 개발 계획서의 RAM·SSD·CPU·네트워크 기준, 5회 반복과 nearest-rank 계산을 공통으로 적용한다. 테스트 파일·캐시·증거는 승인된 작업 루트 또는 별도로 허가된 시험 PC에만 저장한다.
- `필수=yes` 149개는 관련 기술 납품 단계의 필수 검사다. `필수=no`인 Q019–Q021은 G0·G2·G3 수요 가설 검증이며 기술 공개를 차단하지 않는다. 연구 미실시는 untested와 미실시 이유를 공개하고 수요가 입증됐다고 표시하지 않는다. 기술 검사와 수요 검증은 서로를 대체하지 않는다. 명시되지 않은 § 번호는 개발 계획서의 절을 뜻한다.

## 결과 증거의 형식

현재 표는 검사 정의다. 실제 실행 시 별도 결과 레코드에 다음 필드를 모두 저장한다. `status` 허용값은 `pass`, `fail`, `untested`이며 실제 실행하지 않은 행은 `untested`를 유지한다. `defectId`는 결함이 없으면 null로 두며, 문서 구조 검사만으로 제품 행을 pass로 바꾸지 않는다.

```json
{
  "checkId": "F001",
  "status": "untested",
  "buildSha256": null,
  "sourceRevision": null,
  "environment": {"os": null, "cpu": null, "serverVersions": null},
  "fixtureConfiguration": null,
  "procedure": null,
  "actualOutcome": null,
  "expectedOutcome": "해당 검사 행의 합격 기준",
  "evidencePath": null,
  "defectId": null
}
```

실행한 결과에는 null인 build·source·환경·fixture·절차·actual·evidence 필드를 실제 값으로 채운다. 단위검사는 raw report, 전송은 hash·byte 결과, 외부 통신 차단은 capture, 서명은 플랫폼 검증 출력을 첨부한다. 화면만으로 파일 무결성·호스트 검증·egress 차단을 입증하지 않는다. 제품 검사 결과와 문서의 구조·링크·추적 검증 결과는 분리한다.
