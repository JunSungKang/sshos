## 2. 이번 구체화 과정의 설계 결정

사용자가 숫자와 알고리즘까지 정한 것으로 표현하지 않는다. 다음은 대화에서 요구한 기능을 구현 가능한 한 버전으로 고정하기 위한 설계다.

- Windows 11 x64, macOS 14 arm64·x64, Ubuntu 24.04 amd64·arm64의 지원 매트릭스.
- 기본 BrowserWindow 1개와 React DOM 내부 창. Pointer Events, xterm/ssh2, WindowManager의 상태와 접근성 계약.
- 내부 창 12개, 파일 창 6개, 뷰어 4개. 연결 서버 3개, 프로필 10개. 실행 채널은 전체 6개, 서버별 4개.
- GUI 텍스트는 UTF-8 읽기 전용이며 최대 2MiB. 이미지는 정적 PNG/JPEG/WebP이며 최대 20MiB·40MP. GUI 저장·편집은 포함하지 않으며 vi는 PTY에서 사용할 수 있다.
- 파일 더블클릭은 보기로 처리하고, 명시적 실행은 확인 창을 거친다. direct/sh/bash와 argv 배열, POSIX 인용 규칙을 사용하며 GUI 로그와 대화형 PTY를 구분한다.
- 전송은 전체 2개, 서버별 1개이며 read-back과 hardlink를 사용한다. 덮어쓰기·재귀 작업은 포함하지 않는다. 이는 안정성과 구현 범위를 위한 트레이드오프이며 SSH 표준의 필수 조건은 아니다.
- 부작용·exit 결과가 불명확한 상태, 중지 요청 결과가 확인되지 않은 상태, 자동 재실행 금지, 런타임·보안·품질 수치.
- AGPL-3.0-only는 사용자의 취지를 반영한 라이선스 선정 계획이다. GNU 공식 해설에 따른 의무의 한계를 함께 설명하며, 법률 검토를 완료한 것으로 기록하지 않는다.

## 3. 폐기하거나 정정한 이전 해석

v5의 ‘파일만’, ‘터미널 제외’, ‘겹친 창·바탕화면 금지’, ‘파일 미리보기 금지’, 모든 exec를 `/bin/true`로 제한하는 규칙은 사용자의 누적 요구와 충돌하여 폐기했다. X11을 지원하지 않는다는 말은 클라이언트 자체의 창을 구현하지 않는다는 뜻이 아니다. Chromium은 전체 GUI의 렌더링 기반이며, ‘거의 사용하지 않는다’고 기술하지 않는다.

Termix 등의 배포 방식은 각 프로젝트의 공식 문서로 비교한다. 모든 도구에 원격 중앙 서버가 필수라거나 기존 도구에 뷰어·데스크톱 기능이 없다고 주장하지 않는다. 비교 자료는 새 판본의 자료조사를 따른다.

GUI 시안·GIF 요청은 시각 자료 제작 승인이다. 제품 기능 검증이나 제품 구현 착수 승인은 아니다. 이번 전면 개정 지시로 문서 작성은 승인됐으나 제품 구현·외부 공개·Git 쓰기 작업은 실행하지 않았다.

## 4. 변경과 증거 관리

v5와 기존 시안은 `docs/history/v5-before-desktop-20261115/archive-manifest.json`에 해시와 함께 보존했다. 그 이전 history도 수정하지 않는다. v6는 현행 정본이며, 결정되지 않은 사안을 사용자가 승인한 것으로 기록하지 않는다. 구체적인 설계의 실현 가능성은 D01 이후 실제 시험으로 확인한다. 문서 검증은 제품의 무결함 보증이 아니다.
