# sshOS(시오스) 제품 계획서 v6

기준일: 2026-11-15. 대상 제품: 0.1.0. 상태: 문서 개정, 제품 구현 미착수. 사용자는 이번에 모든 계획 문서의 전면 수정을 지시했다. 이 지시는 제품 코드 구현·배포·Git 작업 지시가 아니다. 사용자 결정과 이번 구체화 설계의 출처는 [대화 결정 기록](10-session-decisions.md)에 구분한다.

## 1. 역할과 집중할 사용자

sshOS(시오스)는 **기존 SSH 접속 정보로 Linux 서버에 연결하고, 사용자 PC의 데스크톱 형태 작업 공간에서 파일을 탐색·열기·전송하고 원격 프로그램을 실행하는 클라이언트 앱**이다. 영문은 sshOS, 한글은 시오스, 결합 표기는 sshOS(시오스)다. 제품을 ‘Ubuntu 전용 OS’라고 부르지 않고 지원 서버 목록에 Ubuntu Server 24.04 LTS를 명시한다.

대상은 SSH 계정을 가지고 파일 확인·전달·스크립트 실행을 반복하지만, 여러 도구를 오가거나 모든 기본 작업에 명령어를 입력하는 것을 부담스러워하는 개인 운영자다. 파일의 기본 작업과 실행 창을 하나의 작업 공간에서 처리하는 데 집중한다. 고급 명령은 터미널로 수행할 수 있지만 모든 Linux 명령어에 개별 GUI를 만드는 제품은 아니다.

사용자가 경험하는 기본 흐름은 `앱 실행 → 서버 등록 → 호스트 지문 확인 → 인증 → 데스크톱 → 파일 탐색 → 텍스트/이미지 열기 또는 실행 → 전송/출력/결과 확인`이다. 데스크톱은 시오스 자체의 UI다. 서버의 GNOME/KDE/Windows 화면이나 원격 애플리케이션의 그래픽 창을 전송하지 않는다.

## 2. 확정 범위와 제외 범위

| 구분 | v6 계약 |

| 클라이언트 | Electron, Windows portable .exe / macOS .app. 별도 Node.js·Python·DB·브라우저 설치 요구 없음 |
| 서버 | 기존 SSH/SFTP에 직접 접속. 시오스 전용 서버 앱·중앙 서버·상주 agent·helper·별도 HTTP 포트 없음 |
| 저장 | 로컬 JSON과 OS 암호화. 앱 기능 저장에 DB 서버·SQLite·ORM·IndexedDB·LevelDB 사용 금지 |
| 인증 | 사용자명+비밀번호 또는 사용자명+개인키, 키 passphrase 지원. 지원 형식은 개발 §5 |
| 작업 공간 | 바탕화면, 실행 아이콘, 이동·크기 변경·겹침·최소화·최대화·복원 가능한 내부 창, 작업 표시줄 |
| 파일 | 한 탐색기 안의 트리+목록, 수동 새로고침, 기본 생성·이름 변경·삭제, 비동기 업로드·다운로드 |
| 열기 | UTF-8 텍스트 읽기 전용 뷰어, PNG/JPEG/WebP 이미지 뷰어. 크기·형식 한도는 개발 §18 |
| 실행 | 파일의 명시적 실행 동작으로 원격 스크립트/바이너리 실행, stdout/stderr/종료 상태 표시 |
| 터미널 | SSH PTY 기반 대화형 원격 터미널. 서버에 설치된 vi 등 CLI 프로그램 사용 가능 |
| 상태 | 우측 상단 활성 서버·연결 상태·SSH 응답시간, 하단 상시 전송 진행 선반 |
| 라이선스 | 프로젝트 AGPL-3.0-only 계획. 의존성은 MIT 우선, 그 외 호환 OSS 검토. 정확한 의무와 한계는 자료조사 §8 |

제외: X11/Wayland/VNC/RDP 원격 GUI·화면 전송, 서버 데스크톱 설치, 로컬 OS 터미널, 전용 서비스·프로세스·패키지·방화벽·Docker·DB 관리 GUI, 배포/롤백 자동화, SSH 터널·점프 호스트·외부 agent 인증·MFA, 플러그인·팀 관리 서버. **터미널에서 사용자가 직접 입력하는 명령을 서비스 종류별로 차단한다는 뜻은 아니다.** 원격 계정 권한이 실제 실행 권한이다.

또한 온라인 오류 검색·숨은 브라우저 검색·AI 요약·모델 SDK·에이전트, telemetry·crash 업로드·자동 업데이트는 제외하며 향후 일정에도 예약하지 않는다. 외부 사용자의 파일 변경 실시간 감지·동기화·원격 watcher는 제외한다. 시오스 자신의 전송 진행과 원격 프로그램 출력 스트림은 실시간 표시하므로 이 제외와 혼동하지 않는다.

첫 버전의 GUI 파일 작업은 읽기 전용 내용 보기, 일반 파일 전송, 단일 폴더 생성, 같은 폴더 일반 파일 이름 변경, 일반 파일/빈 폴더 삭제로 한정한다. GUI 내용 편집·덮어쓰기·권한 변경·재귀 폴더 전송/삭제·폴더 이름 변경·항목 이동·서버 간 복사·링크/특수파일 조작·전송 일시정지/이어받기·자동 재접속은 제외한다. 이 한정은 구현 가능한 첫 버전을 위한 설계 결정이지 사용자가 모든 기능을 금지했다고 추정한 기록이 아니다. 터미널에서 vi로 저장하거나 chmod를 실행하는 것은 GUI의 제한과 별개다.

## 3. 지원 환경과 설치 없는 실행의 의미

| 위치 | 지원 목표와 제한 |
| --- | --- |
| Windows | Windows 11 x64 |
| macOS | 최소 macOS 14, arm64/x64 별도 배포. 공식 검증은 macOS 14 두 CPU. 추가 major는 실제 시험 후 목록에 추가 |
| Linux 서버 | Ubuntu Server 24.04 LTS amd64/arm64, 기존 OpenSSH. 파일 기능은 SFTP, 실행은 exec, 대화형 터미널은 PTY 허용 필요 |
| 프로그램 | 서버에 이미 존재하고 계정이 실행 가능한 CLI 프로그램. 시오스가 interpreter·패키지·실행 권한을 자동 설치/부여하지 않음 |
| 로컬 파일 위치 | APFS(macOS), NTFS(Windows) 일반 파일/폴더. 네트워크 볼륨·클라우드 placeholder·FAT/exFAT 지원 제외 |
| 업로드/이름 변경 | 기존 파일 보존을 위한 같은 디렉터리 hardlink 지원 필요. 미지원 시 해당 기능만 제한 |

Windows .exe는 내부 파일을 임시 해제할 수 있고 macOS .app은 여러 파일을 묶은 bundle이다. ‘하나를 실행’은 설치 마법사와 외부 런타임 설치가 없다는 뜻이며 물리 파일 하나·캐시 0개라는 뜻이 아니다. 설정은 실행파일 옆이 아닌 사용자 데이터 디렉터리에 저장한다. Electron의 용량·메모리 비용은 개발 §14에서 측정하고 측정 전 ‘가장 가볍다’고 주장하지 않는다.

OS 자동 확인은 SFTP의 `/etc/os-release` 읽기로 한다. 확인 실패는 세션별 ‘Ubuntu 24.04임을 사용자 확인’ 후 기능을 연다. 다른 OS가 확인되면 조회만 가능하다. SFTP 없는 SSH에서도 사용자 OS 확인 후 터미널을 사용할 수 있다. SFTP-only 계정은 파일 기능을 사용할 수 있지만 exec/PTY가 거부되면 실행/터미널은 사용할 수 없다. ‘SSH만 있으면 모든 권한과 프로그램이 생긴다’고 안내하지 않는다.

## 4. 데스크톱 경험

한 Electron 기본 창 안에 시오스 내부 창을 표시한다. 고정 좌측 메뉴로 화면 전체를 교체하는 v5 구성을 폐기한다. 바탕화면의 연결·파일·터미널·설정 아이콘, 작업 표시줄의 실행 중 창 목록, 전송 선반의 전체 작업 버튼을 제공한다. 파일 트리와 목록은 같은 탐색기이며 둘을 별도 메뉴로 분리하지 않는다.

내부 앱 종류는 연결 관리자, 파일 탐색기, 텍스트 뷰어, 이미지 뷰어, 실행 출력, 터미널, 작업 관리자, 설정이다. 서버 작업 창의 제목에는 서버 표시명을, 상세에는 사용자·주소·경로를 표시한다. 창 포커스를 다른 서버로 옮기면 상단 활성 서버만 바뀌고 이미 실행 중인 작업의 대상은 바뀌지 않는다.

최소화는 화면을 숨길 뿐 작업을 취소하지 않는다. 복원 시 위치·크기·내용·서버 귀속을 유지한다. 닫기와 실행 중단은 별도 동작이다. 동작·키보드·좌표·창 수·서버 선택 규칙의 정본은 [데스크톱 상세 명세](09-desktop-interaction-spec.md)다. GIF는 일부 동작을 설명하는 예시이며 세부 기능 완성 증거가 아니다.

## 5. 파일 탐색·열기·실행

| 사용자 행동 | 결과 |
| --- | --- |
| 폴더 열기 | 같은 탐색기의 트리 선택·경로·목록 갱신 |
| 일반 파일 더블클릭 | 열기 판정에 따라 텍스트/이미지 뷰어. 불명 형식은 형식 선택/다운로드 안내. 실행하지 않음 |
| .sh 텍스트 열기 | 코드가 문자로 표시됨. 자동 실행 없음 |
| 파일 메뉴의 실행 | 서버·사용자·전체 경로·작업 폴더·실행 방식·인수 확인 후 원격 실행 |
| 터미널 열기 | 선택 서버의 대화형 셸. 파일 창과 별개이며 창 크기를 원격 PTY에 반영 |
| 새로고침 | 서버에서 다시 조회. 마지막 조회 시각 표시. 다른 사용자 변경 자동 감지 없음 |

GUI 뷰어는 저장 버튼이 없는 읽기 전용이다. 텍스트 읽기와 목록 조회에 vi/ls를 실행해 출력을 파싱하지 않고 SFTP를 사용한다. vi 자체를 원하는 사용자는 터미널에서 실행한다. 파일 실행은 직접 실행 또는 사용자가 선택한 `/bin/sh`, `/bin/bash`로 수행하고 기본 권한·실행 형식 오류를 사실대로 표시한다. GUI 프로그램을 실행해도 그 그래픽 창은 표시하지 않는다.

## 6. 비동기 전송과 기존 파일 보존

전체 동시 전송 2개, 서버별 1개, 대기 100개. 창 전환·탐색기 닫기·내부 창 최소화 뒤에도 전송은 유지된다. 선반에는 서버, 방향, 파일명, 처리 byte/전체 byte, 단계, 속도를 항상 표시한다. 전체 작업 창에서 모든 작업을 확인한다.

같은 목적지 이름이 있으면 다른 이름·건너뛰기·취소 중 선택한다. 임시파일에 전송한 후 SHA-256 read-back 대조, 목적지 배타 생성, 기록 저장까지 완료해야 완료로 표시한다. read-back은 업로드 데이터를 다시 읽어 트래픽·시간을 증가시킨다. hardlink 미지원 환경에서는 기존 파일 삭제/덮어쓰기로 우회하지 않는다. 원본 권한·소유자·mtime·ACL을 복제하지 않는다. 새 파일 요청 mode0600, 새 폴더0700이다.

연결 단절 후 확인하지 못한 결과는 ‘결과 확인 필요’다. 자동 재전송·프로그램 재실행·잔여파일 자동 검색/삭제는 없다. 전송 취소와 실행 중지 요청의 의미가 다르므로 개발 §8과 §19를 각각 따른다.

## 7. 연결 상태와 SSH 응답시간

우측 상단은 활성 서버의 `서버명 · 연결됨 · SSH 응답 84 ms`를 표시한다. 숫자는 예시다. `/bin/true` 요청 직전부터 정상 exit와 채널 close까지 측정하며 순수 네트워크 RTT·ICMP ping·서버 건강도 점수가 아니다. 고정 명령 제한은 이 측정 기능만의 규칙이다. 사용자가 요청한 원격 실행과 터미널 입력은 별도 계약으로 허용한다.

| 조건 | 문구 |
| --- | --- |
| 정상 | SSH 응답 84 ms; 1ms 미만은 SSH 응답 <1 ms |
| 처음 요청 | 측정 중 |
| 5초 초과 | SSH 응답 지연 |
| 요청 거절/실패/종료정보 없음 | 응답시간 측정 불가 |
| 채널 대기 / 앱 비활성 | 측정 대기 / 측정 일시 중지 |
| 연결 해제 | 연결 끊김; 숫자 제거 |

측정 종료 5초 후 다음 측정, 15초 지난 값 폐기, 앱 비활성·최소화·절전 동안 측정 중지. 여기서 최소화는 시오스 전체 기본 창이며 이미지 등 내부 창의 최소화는 해당하지 않는다. 실패만으로 파일 전송/터미널을 끊지 않는다. 설명 문구는 ‘현재 SSH 연결에서 짧은 명령의 완료 응답을 받는 시간입니다. 네트워크와 서버 처리 시간이 포함됩니다.’로 고정한다.

## 8. 신뢰·저장·권한

비밀번호·키 passphrase 저장은 기본 꺼짐이며 요청 시 OS 암호화 후 JSON 저장한다. 개인키 원본을 서버로 보내지 않는다. 신규 호스트 지문 승인과 변경 키 차단을 모든 SSH socket에 적용한다. 원격 데이터는 신뢰하지 않으며 HTML 실행·브라우저 이동·클립보드 변경을 유발할 수 없다.

임의 명령 실행은 사용자가 선택한 원격 계정의 기능이다. GUI의 파일 보호 제한은 터미널이 실행한 명령·다른 프로그램·다른 접속 사용자를 통제하지 않는다. 시오스는 원격 권한 상승을 자동 수행하지 않는다. 원격 명령이 외부 통신하거나 파일을 수정할 수 있다는 사실을 숨기지 않는다. 클라이언트 자체의 자동 통신은 대상 SSH와 DNS뿐이다.

프로필·신뢰·설정·작업 상태는 로컬 JSON이다. 원격 파일 내용·터미널 입출력·원격 실행 인수는 디스크에 자동 기록하지 않는다. 기록에 남는 서버·경로는 익명 정보가 아니며 디스크 보호의 한계도 개발 계획에 명시한다.

## 9. 실제 사용 가치와 검증

핵심 가설은 ‘SSH 계정만 가진 사용자가 파일과 실행을 데스크톱 창으로 함께 다루면 작업 맥락과 대상 서버를 이해하기 쉽다’다. 유사 도구도 파일 뷰어·터미널을 제공하므로 기능의 존재만으로 독점적 차별성을 주장하지 않는다. 기본 흐름의 일관성, 서버 귀속 표시, 별도 서버 구성 없는 시작, 대기와 불확정 결과의 설명을 검증한다.

G0: 최근 3개월 SSH 파일/실행 경험자 6명 인터뷰, 4명 이상이 실제 반복 불편을 설명하면 문제 가설을 유지한다. G2: 12명에게 평소 도구와 시오스로 접속·탐색·보기·전송·프로그램 실행·느린 응답·단절 확인을 수행하게 한다. 순서는 6명씩 교차 배정한다. 정상 과업 독립 완료10/12, 두 장애 과업 결과/서버 식별9/12, 오서버 변경·거짓 완료0건을 목표로 한다. 미지원 업무와 불편을 숨기지 않는다. G3: 6명 4주 pilot, 기회2회 이상인 사람4명 이상 중3명 이상이 강제 없이2회 이상 사용하면 반복 사용 가설을 지지한다. 기회 부족은 관찰 부족이다.

이 표본과 수치는 설계 목표이며 연구 논문의 검증 결과가 아니다. 사용자 연구 미실시는 수요 검증 미완료로 공개하고 기술 구현을 막는 외부 승인으로 사용하지 않는다. 외부 시험/배포에는 개발 §14와 체크리스트의 기능·보안·플랫폼 기준이 필요하다. 무결함·경쟁 도구보다 빠름·시장 수요 입증을 검사 없이 주장하지 않는다.

## 10. 문서 우선순위와 구현 순서

사용자의 최신 지시가 문서보다 우선한다. 제품 범위는 이 문서, 실행·보안·수치는 개발 계획, 내부 창의 조작은 데스크톱 상세 명세를 정본으로 한다. 상호 충돌은 관련 기능의 구현 전에 수정한다. 기계 명세·체크리스트·시안은 범위를 임의 확대/축소할 수 없다. 이전 판본은 history에 보존한다.
